## Confirmed finding

```text
SEVERITY: MAJOR
WHERE: J14, run page (isolated home /private/tmp/agentdeck-usability-2026-09-26.eeqMfr/homes/j14, port 4414), FS-14.R36–R37
REPRO: Save a four-stage Work → Review → Validate → Complete template; start it on Review Workspace; on its run page compare the run badge with the current stage's attempt row; wait three seconds and refresh.
EXPECTED: Once the Work attempt is running, the run page reports the run as running, consistently with its current stage and attempt.
OBSERVED: The run badge remains QUEUED while the page shows Work, Stage 1 of 4, and Work · attempt 1 as RUNNING; the contradiction remains after waiting and refresh. The person cannot trust the primary run status to tell whether work has begun.
EVIDENCE: usability-review-2026-09-26-evidence/j14-run-page-stage-one.png
```

**Proportionate improvement:** Keep the run-page status synchronized with the durable run/attempt lifecycle; verify the badge moves from queued to running as soon as the first stage attempt runs and remains consistent after refresh. This is a **Must fix** because it presents stale lifecycle state during ordinary run supervision.

## Not exercised

Real-provider authentication/model behavior, native macOS file pickers, real terminal hooks/provider CLI behavior, file-viewer link paths, and several deeper task/pipeline recovery permutations remain unverified. The isolated run does not establish behavior in those branches.
