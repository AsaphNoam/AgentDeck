# Build and run pipelines

Pipelines are saved, model-neutral templates whose stages run as bounded durable assignments to one standing run orchestrator, with persisted stage outputs and operator recovery.

- A template is an ordered list of required stages: no conditional skips, backward routes, loop counters, or prescribed child task graph. Validate a template before starting it. Success advances to the next stage; failure or `blocked` pauses the current stage for recovery. A stage may keep an explicit human approval gate before advancement.
- Starting a run selects the project, goal, named inputs, and one backend/model for the standing orchestrator. A stage configured for dedicated coordination also selects its sub-orchestrator's role and runtime; other stages supply instructions only, and never a different role or runtime for the standing orchestrator.
- Every stage arrives as an assignment to that same standing orchestrator, carrying the run goal, the stage objective, its context and instructions, the expected output, and the durable outputs earlier stages produced. Conversation continuity is useful context, never the authority for workflow position: read the assignment, not the transcript.
- Only an outcome AgentDeck accepts from the standing orchestrator holding the active stage can complete that stage. Idle, process exit, and the aggregate state of child work never substitute for its report, and a person cannot mark a stage passed without one. A rejected report leaves the assignment actionable; a duplicate or stale report cannot complete a later assignment.
- Inside the active stage, the standing owner and any delegated coordinator decide decomposition, delegation, reviewer selection, repair routing, and whether re-review is needed. A failed, blocked, cancelled, or replaced child task does not by itself block or advance the pipeline. Keep repair loops inside the stage and report the stage outcome once.
- When a stage is configured with dedicated coordination, AgentDeck creates one managed child task beneath the stage assignment and launches its sub-orchestrator there. That sub-orchestrator is the normal coordination contact and the authoritative source for its delegated work, and it reports upward; its result cannot advance or close the stage. The standing owner evaluates that report and keeps the final stage decision. It may inspect descendants or intervene directly — that transfers no ownership — and should send material intervention as best-effort deferred mail, which reaches the coordinator on its next natural turn.
- At accepted completion the stage closes to new work and its unfinished descendants are cancelled, and cleanup must finish before the next stage starts. Do not plan for child work to outlive the stage that created it. Transient cleanup failures retry automatically, so a run reporting that cleanup is retrying does not need a person.
- `blocked` returns control to the human. Continue supplies new input and creates another stage assignment on the same standing orchestrator; Retry re-runs an interrupted assignment on its existing assignee; Replace cancels an unfinished stage assignment and issues a replacement carrying durable stage context while retaining existing child work. None of them rewrites an accepted result, and none continues a blocked stage inside its existing chat turn.
- Stop closes the run to further work and cancels every unfinished stage task and descendant, including queued, waiting, retrying, and nested delegated work. Nothing delegated keeps running afterwards. Completed results stay immutable and the run record is not erased.
- Stage outputs live in AgentDeck's durable run and task records and stay inspectable after completion. Persisted outputs, not transcripts, are what later stages and supervision read.
- A run may reach several repositories, but only ones the run's existing AgentDeck project configuration already reaches. The pipeline grants no cross-project access and no additional filesystem roots.
- Owning an active run does not make an agent unaddressable, but stage work reaches the standing orchestrator through its current durable assignment; an unrelated task assignment cannot take that agent over while the run owns it. Normal messaging, resume, archive, and task-target rules apply again once run ownership ends.
- AgentDecker may propose a template or exact run configuration only for human review. A proposal neither saves nor starts anything; the operator confirms those actions in AgentDeck. Other roles do not gain proposal authority from this skill.

Use the pipeline tool definitions and CLI help for exact arguments and current result fields.
